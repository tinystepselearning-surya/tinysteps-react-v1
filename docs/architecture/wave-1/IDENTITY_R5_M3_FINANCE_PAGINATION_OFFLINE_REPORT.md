## 2. Financial semantics retained

The existing pure report, allocator, hash function and write planner are imported unchanged. Report inputs remain the selected payments with allocation subdocuments, active charges, complete scoped wallet ledger, wallet summary, stored month models and profile labels. The reference loads every synthetic row for the declared parents without pagination, then invokes those existing reducers. This is an exhaustive **synthetic-source differential reference**, not an independent reimplementation of every accounting rule.

Additional independent arithmetic coverage uses a cents-only FIFO ledger across 32 deterministic datasets with fractional amounts. It verifies old-wallet-only allocation into older dues, residual advance and preservation of historical opening/refund balances. Existing finance suites cover partial/full/overpayment plans, duplicate suspicion, mixed schemas, already-current skipping, charge/month projections, source-verification snapshots and idempotent rerun after simulated patches. This combination tests traversal equivalence and established financial expectations; it is not a formal proof for arbitrary historical data.

Preserved behavior includes: receipt-month filtering; full historical ledger balances; archived payment handling; exclusion of archived/void/cancelled/reversed/refunded charges; negative/zero payment diagnostics; signed refund/reversal entries; existing allocation-document precedence over inline allocation hints; warning/anomaly gating; and legacy hash normalization. Duplicate transport pages deduplicate document identities, while distinct documents with a duplicate financial transaction ID remain visible and produce the existing anomaly. No financial record is “corrected” by the reader.

Identical complete source sets yield identical reports (excluding generated clock metadata), legacy report hashes and write plans. This does **not** claim equivalence to the current truncated selection: completing a previously truncated parent/global scope intentionally changes its input population and can change totals, eligibility and hashes. That is an owner decision for integration.

## 3. Isolated pagination prototype

Files: `functions/test/support/financeReadPagination.ts` (pure injected runner), `financeSyntheticSource.ts` (memory-only adapter/reference), `financeLegacyDb.ts` (recording fake for existing loaders). Nothing is imported by `functions/src`, the browser application, deployment entrypoints or production configuration.

The declared manifest names 1–12 unique synthetic parent identifiers. Each parent has six base scopes: payments, charges, transactions, months, wallet and profile. Each discovered payment adds its own allocation scope. Transport traversal is deterministic by document ID; after complete collection, the unchanged financial reducer supplies its existing financial ordering. This avoids pretending that transport ID order is payment chronology. The adapter uses opaque, query/parent/payment/revision-bound HMAC cursor tokens; tokens are deterministic within one adapter instance and cannot be moved to another scope. There is no external resume-token API or persisted checkpoint. A future resumed run would require its own versioned scope/consistency contract.

| Limit | Default | Enforcement |
| --- | ---: | --- |
| Page size | 20 rows | Every injected page request; configurable maximum 100 |
| Per-query returned rows | 200 | Includes duplicate pages; all collection scopes including allocations |
| Per-query page attempts | 30 | Includes retries and empty terminal probes |
| Per-parent rows / page attempts | 1,000 / 200 | Shared across all base and allocation scopes |
| Whole-run returned rows / source calls | 4,000 / 800 | Concurrent page capacity reserved before requests; calls include begin/end and retries |
| Concurrent allocation requests | 3 | Independent worker pool; configurable maximum 8 |
| Retry allowance | 2 | Consecutive transient errors or repeated pages; configurable maximum 3 |
| Whole-run / request time | 5,000 / 500 ms | Deadline and AbortSignal; late responses ignored |

Limits are positive safe integers (retries may be zero); broad test configuration ceiling is 100,000 for numeric limits except the stricter page/concurrency/retry ceilings. These are **test-prototype defaults**, not approved production budgets. Wallet/profile are represented as at-most-one-record scopes in this adapter; a production point-read adapter has not been designed. Every nonempty page needs a cursor; exhaustion requires an empty terminal page. At an exact row cap with no capacity left to probe, the result is incomplete, conservatively. More rows cannot be fetched merely to settle the ambiguity.

| Result | Meaning / output contract |
| --- | --- |
| `COMPLETE` | All declared scopes exhausted and final whole-scope revision matches. An in-process private capability allows evaluation of a copy of collected rows and calculation of the legacy comparison hash. `writeAuthorized` remains false. |
| `INCOMPLETE_BUDGET` | Row/attempt/operation/deadline budget, transient retry exhaustion or repeated-page no-progress. No rows, financial report, safe decision or report hash is exposed. |
| `INCOMPLETE_CONCURRENT_CHANGE` | Page/final revision drift or the same document reappears with a different version/data fingerprint. No report or hash. |
| `INVALID_SOURCE` | Invalid manifest/page/order/cursor/scope/data, oversized response or non-transient provider error. Fixed reason codes, no raw source errors or partial data. No report or hash. |

A cloned/forged COMPLETE object cannot recover data or invoke evaluation. Each trusted evaluation receives a new copy so evaluator mutation cannot alter the retained source. This capability is an accidental-misuse guard for offline code, not a sandbox against arbitrary code in the same process. The prototype validates the transport contract, not every possible financial-schema defect; the existing financial reducer remains responsible for domain diagnostics.

### Source-consistency boundary — unresolved for real Firestore

The source contract requires a monotonic revision for **all declared scopes**, including insertions/deletions in previously empty scopes and every allocation child. Tests mutate payments and empty allocation scopes before final validation and reject the result. An individual document updateTime, a maximum timestamp, two matching page counts or a hash of only observed rows does not meet this contract. An adapter that silently omits rows or lies about its revision is outside the demonstrated guarantee.

No real Firestore snapshot/revision adapter, timestamp codec, index plan, SDK retry accounting or cancellation guarantee is implemented. The synthetic adapter normalizes data to finite JSON; real Timestamp/Date representations must preserve financial interpretation in a separately reviewed codec. AbortSignal bounds this runner’s waiting and scheduling, but does not prove physical cancellation of an SDK RPC. Failed RPCs may consume reads even when no rows are returned. `pageAttempts` counts scheduled attempts, including an attempt stopped before dispatch by the run-call budget; returned-row metrics count pages accepted by this runner, not late discarded responses. These remain explicit integration blockers; the prototype must not be copied into deployed functions as-is.

## 6. Owner decisions and recommended implementation sequence

1. **P1 — define the financial completeness contract before integration.** Decide whether payment caps mean an explicitly partial preview or a fully audited selected parent. Approve parent discovery (including parents with zero payments), receipt-month vs service-month scope, historical ledger/charge requirements, missing/equal timestamp ordering and archive/refund policy. Do not silently replace global limited selection with “earliest N” or cut history at a date.
2. **P1 — prove consistency and fail closed.** Choose a supported consistent snapshot or whole-scope revision mechanism covering absence, insertion, deletion and allocation children. Establish a real adapter and timestamp codec in a later reviewed change. Incomplete data must never enter eligibility/write planning. Transaction checks must bind the approved complete source, including changes outside previously selected IDs.
3. **P1 — version the evidence/authorization boundary.** Keep the existing financial hash unchanged for compatibility comparisons, but design a separate versioned completion certificate binding manifest, filters, ordering, source revision and normalized report hash. Decide whether every write must require that certificate/hash. The current optional-hash and single-parent-filter mismatch must be resolved deliberately with consumer/UI changes and finance-owner approval, not bypassed.
4. **P2 — budget the entire operation.** Approve per-query/parent/run rows and calls, independent allocation concurrency, retries, terminal probes and cancellation behavior. Instrument SDK attempts separately from returned rows and production billing. Extend bounded traversal to adjacent reconciliation and wallet-history paths; retain explicit incomplete states instead of treating warnings as successful full audits.
5. **P2 — integrate behind an offline/emulator gate in a separate PR.** Keep dry/write shared source selection, add real-adapter emulator cases for timestamp types, indexes, inserts/deletes, cross-parent isolation and actual transaction retries, then repeat differential/hash/idempotency tests. Any new indexes, financial semantics, runtime changes or deployment require their own reviewed approval. Issue #706 must be owner-approved before authenticated production verification with approved identities/resources.

**Readiness verdict:** the offline engineering batch is reviewable; the production finance-completeness gate is not satisfied. Milestone 3 remains **IN PROGRESS**. No production read, financial write, backfill, correction, role/permission change, deployment, Rules cutover or authenticated canary was performed. Auto-merge must remain disabled.
