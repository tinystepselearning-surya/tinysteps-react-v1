## 1. Integrated delivery chain

DeliveryOffering -> Enrollment or LearningGroup -> effective TeachingAssignment and SchedulePlan -> virtual timetable occurrence -> actual ClassSession (only on authorized action) -> SessionParticipant and SessionStaff -> official AttendanceRecord + correction history -> Finance (charge/earning eligibility) and LearningActivity/evidence -> course and mastery projections -> authorized portal views.

A virtual occurrence is a computed calendar expectation, not an actual session, financial event or evidence of teaching. Schedule, attendance, learning, Finance and provider evidence have independent facts and owners. Group delivery has one occurrence with many participant records; 1:1 has one participant. Historical source aliases and snapshots remain readable. School daily register is a distinct attendance context, not an online billable class. Admissions demo remains Admissions-owned, not an academic ClassSession.

## 2. D05 — Schedule and classroom records

| Code | Candidate path | Grain / disposition |
|---|---|---|
| SCP SchedulePlan | schedulePlans/{schedulePlanId} | One effective recurring plan for enrollment OR learning group; candidate extraction from enrollment.schedule |
| SEX ScheduleException | scheduleExceptions/{exceptionId} | One occurrence-level override/cancel/move; candidate, effective history |
| SES ClassSession | classSessions/{sessionId} | One real academic occurrence; preserve source ID, date/time and protected history |
| SPT SessionParticipant | sessionParticipants/{participantId} | One learner enrollment participating in actual session; candidate, no duplicate per session/learner |

| RFL RecordingFolderAccess | parentClassRecordings/{recordingId} | Existing parent folder-access surface; preserve current access and URLs until reconciled |

All new paths require collision, writer, index and authorization review. No blanket copy of classSessions into another root. A plan revision and planned occurrence do not create a session. Preserve source contract schemaVersion, weekly slots (weekday, time, durationMinutes), revision, effective dates, provider join URL and schedule lifecycle. Target recurrence is bounded and typed, with explicit local time, IANA timezone and revision; existing SCP-1005 remains unresolved structured field until schema adoption, not arbitrary JSON. An exception has a stable original occurrence reference, reason, action and revision; a reschedule links original/replacement explicitly and retains history. No automatic credit creation. Preserve cancellation/paused/discontinued, teacher reassignment, ad hoc and retry behavior; protected completed/attended/financial occurrences cannot be rewritten by timetable changes.

**Critical cutover:** legacy14DayCutover.ts sets LEGACY_14_DAY_SESSION_WRITES_RETIRED and AUTOMATIC_SESSION_CREATION_RETIRED to true; dayWindowTimetableSync checks the latter and returns early. Some old lifecycle comments mention next-day creation, but they do not override the actual retirement guard. Do not re-enable 14-day, next-day or background session creation as a V2 rollback. Student Management remains timetable authority. Existing authorized teacher attendance and ad hoc commands materialize real sessions on demand. Keep no unnecessary writes for merely viewing future schedules. Preserve current retirement flags, rolling compatibility API and exact on-demand authorization until reviewed replacements pass parity.

**Time contract:** Current rolling schedule supports Asia/Kolkata, converts IST date/time into UTC instants, and existing claim keys use child + IST date + start time (not enrollment). Retain serviceDateYmd (IST for existing online business), startAt/endAt timestamps and original local plan date/time/timezone. Do not substitute viewer-local date for attendance, finance, claim or recurrence keys. Parent/teacher local timezone is presentation context, not schedule ownership; display both respective local time and IST, including correct local day/date and DST offset. For future other-zone delivery only after ADR: explicit schedule timezone and separately approved service-day policy, deterministic DST gap/overlap handling, preserve UTC instant and original wall-clock input; never change existing recurring time by inference. Missing timezone history stays unknown or source-verified IST only. No scheduled occurrence before valid enrollment start. UTC midnight and IST day rollover tests mandatory.

**Identity/concurrency:** Existing rollingSessionId(enrollment,date,startTime) and calendarAttendanceClaimId(child,date,startTime) remain current compatibility keys; the claim deliberately ignores enrollment ID. Preserve same learner/time cross-enrollment collision checks, teacher/student overlap checks, protected snapshots and stable occurrence IDs. Candidate group key design uses verified group occurrence plus participant uniqueness and applicable per-learner slot claims; no artificial separate real session for each group participant. Transactionally reserve occurrence and participant keys, check source revision and scope, and use operation IDs for retries. Session staff/participants carry historical assignment/enrollment references and only minimum required snapshots. Do not infer absent participants from current roster. No indefinite arrays, no whole-collection scan.

**Meeting/recordings:** preserve existing parent classroom join link semantics, Teams meeting references, student recording folder routing and existing parentClassRecordings access until integration mapping verified. A recording is an asset/provider reference with provenance and permission state; association may be session-specific or verified learner-folder scope, not necessarily one recording per session. Never infer a session or grant access from filename alone. Do not store public URLs as canonical entitlement; provider permission and app permission independently enforced. No automatic sharing, raw transcript import, OneDrive folder moves, or recording re-routing in design. D10 integration review must reconcile external router and actual folder access privately before any change.

## 3. D06 — Official attendance, evidence and corrections

| Code | Candidate path | Grain / disposition |
|---|---|---|
| ATT AttendanceRecord | attendanceRecords/{attendanceId} | One official decision per actual participant/context; candidate extraction from classSessions.attendance |
| ACR AttendanceCorrection | classSessions/{sessionId}/attendanceCorrections/{correctionId} | Preserve existing correction event, potentially multiple participant changes; append-safe history |
| AEV AttendanceEvidence | attendanceValidationEvidence/{evidenceId} | Existing validation evidence store; restricted provider evidence, not official decision |
| AVC AttendanceValidationCase | attendanceValidationCases/{caseId} | Existing AVS comparison/review workflow; preserve evidence and resolution links |
| AVD AttendanceValidationResolution | attendanceValidationResolutions/{resolutionId} | Existing workflow decision evidence; not automatically official attendance |
| SAD SchoolAttendance | schoolAttendanceRecords/{recordId} | Candidate school daily register per learner/institutional placement/service day; separate policy from online session attendance |

ATT status present/absent for new online marking; unmarked = no official decision, never automatic absence. Preserve raw historical late/no_show/noshow and other source statuses, only normalize with existing reviewed meaning; legacy financially-earned present/late behavior must remain until explicit policy decision. ATT revision and scope must be explicit; correction must capture before/after, reason, actor, source revision, time and financial-review link as needed. For existing correction events preserve multi-child grain rather than inventing one historical event per child. Record official mark and correction evidence atomically where same-database transaction supports it; external evidence and finance are separate idempotent boundaries. Teacher may correct own eligible session through existing authorized workflow; Admin correction remains available under existing policy. No new role rights. AVD records approved AVS outcome; only authorized existing attendance command may change official record. Preserve dirty markers, runs, cases, identity claims, baselines and evidence freshness; do not duplicate AVS authority or turn unresolved mismatches into automatic status changes. Provider unavailable, missing identity mapping, stale evidence or no match are inconclusive, not proof of absence. Avoid raw Teams identities/attendance logs in portal views.

**Finance boundary:** saveTeacherSessionProgress validates present/absent, checks membership/version and claims, uses attendanceOnly to avoid unrelated progress changes, and writes correction evidence. sessionRevenue consumes classSessions updates, uses historical financial terms snapshots and attendanceFinanceCycle, and protects paid/settled/unsafe ledgers. Preserve present-only new marking, historical earned-status interpretation, current completion eligibility, session charge/earning keys, idempotent reopen/void behavior and settled correction review. Do not post from virtual occurrence, AVS evidence, learning observation or a school daily mark. Do not create duplicate charge/earning during extraction; maintain current trigger compatibility until D08 defines authoritative posting contract, versioned event and reconciliation. Separate correction of attendance from financial adjustment; no automatic reversal of settled ledgers. Group participant finance grain and per-staff earning allocation require D08 review; preserve existing session-level source identity, no guessed splits. Historical price/currency/teacher pay snapshots retained without recomputing using current fees. No finance data migration in M02.

| SAG SchoolAssessmentSummary | schools/{schoolId}/academicYears/{yearId}/assessmentSummaries/{assessmentId} | Existing institutional aggregate; never infer individual scores |

Preserve existing students/{kidId}/curriculum and progress/{topicId} under their current operational owners and legacy consumers until field-level mapping and writer review. Current saveTeacherSessionProgress writes topic completion and individual progress in its transaction; direct progress editor is also catalogued. Never replace an existing teacher remark or completion with a synthetic assessment. Topic/course IDs, curriculum stages and lesson catalogue references require verified mappings before association with CUR/UNT/SKL/LSN. Preserve teacher session workflow and attendanceOnly behavior. Do not force a completed lesson to imply mastery or a game attempt to imply standardized assessment. Keep actual evidence, teacher observation, assessment result, feedback and derived progress distinct. Source school reading-level reference is internal implementation guidance, not age norm or standardized benchmark.

Proposed validation: published lesson/assessment/rubric versions immutable (retire prevents new use, never removes historical reference); assignment -> submission attempts -> feedback; append corrections/superseding evidence rather than destructive edits. Assessment records preserve version, method, assessor/actor, observed time and verified scoring criteria/units; no uniform score conversion without rubric mapping; absent assessment = unassessed, not zero. Observation distinguishes what was observed from interpretation/next action; minimum necessary content and purpose. SkillEvidence references exactly one approved source type/id and relevant skill version interpretation; derive mastery with approved versioned algorithm, source watermark and evidence sufficiency; unknown/unassessed distinct from low mastery. No AI-generated observations automatically stored as truth. Existing game result events can contribute only via validated evidence contract; do not invent outcomes or assume game skill tags map one-to-one to curriculum. Rebuild course/mastery projections idempotently; no unbounded evidence arrays, no cross-tenant aggregate exposure. School aggregate stays at school/year/section grain with existing counts, distribution and version; no individual record reconstructed.

Audit actor and revision without logging raw sensitive content.

Candidate query shapes: target + effective schedule range; tenant + teacher/learner + bounded calendar date/time window; participant/staff by exact session or scoped learner/teacher + time range; attendance by session/participant or scoped learner + service-date range; validation case by approved enrollment/date and state; activity/evidence by scoped enrollment/learner + curriculum/skill + bounded time range; current progress projection by exact context key. Review actual indexes and native/legacy consumers, enforce pagination and limits, preserve existing optimized projections; no per-item registry reads or N+1 per-lesson/student lists. Measure calendar read counts, writes per view (zero business writes target), attendance transaction cost incl. claims/Rules, correction/trigger costs, projection freshness and resource access; use comparable fixtures and actual baseline before numeric budgets. No index or runtime deployment. Provider ingestion, backfill and reconstruction have separate approved ceilings; no automatic broad historical scan.

## 6. Migration and verification

1. Reuse current SES IDs, calendar claims, correction events, AVS stores, Teams links, content resources, progress and aggregate school records. Preserve exact source values and compatibility until reviewed migration. Candidate roots/fields unallocated.
2. For SCP/SEX, derive from verified recurrence/revisions and exception history; do not materialize historical/future session records merely from plan. For SPT/SST extract verified historical occurrence participants/staff, quarantine ambiguous aliases. Do not assume enrollment's current teacher is past teacher.
3. For ATT, map official source session attendance by verified participant, preserve raw status/provenance/correction history, do not infer absence. Never reconstruct AVS from Teams filename or create duplicate financial events. Preserve historical finance terms and existing trigger behavior; D08 approval prerequisite to any attendance authority switch.
4. For learning, map course/topic/session records and evidence only where identity/version/source verified. Leave history unassessed/unknown when absent, introduce new observation/assessment capture prospectively after approved implementation. Preserve school aggregate history and legacy progress; no invented individual assessments.
5. Preflight exact cohort, bounded reads/writes, idempotent IDs and checkpoints, conflict quarantine, independent reference/history/semantic reconciliation, finance control totals, provider permission and link validation, read/latency comparison; do not mutate original until approved cutover. Keep single write authority, controlled catch-up, shadow comparison, rollback preserving post-switch writes, explicit retention/retirement gate. No production backup or restore claim.

Required test matrix (design scenarios, not executed runtime tests): IST/UTC/local date rollover and DST display; same learner/date/time duplicate across enrollments; overlapping teacher/student; timetable edit no automatic materialization and protected session immutable; group participant split without duplicate session; on-demand retry idempotent; unauthorized teacher and cross-tenant participant denied; unmarked distinct from absent; historical late preserved; attendanceOnly no learning writes; correction paid/settled ledger held and no duplicate earnings; stale/missing provider evidence inconclusive; wrong guardian/recording scope denied; course change and teacher change preserve past evidence; new rubric/lesson version preserves historical references; unknown mastery not zero; aggregate school evidence not expanded into individuals; projection replay/freshness and bounded reads; recovery and rollback preserving post-cutover evidence. M04 completes exact field shapes, source coverage, command contracts, state transitions, indexes, policy and test plans.
