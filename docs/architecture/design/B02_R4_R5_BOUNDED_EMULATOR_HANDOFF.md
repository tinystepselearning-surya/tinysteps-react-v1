## Proposed R5-A backend experiment (not executed)

One disposable emulator-only experiment for transaction semantics, not a real finance adapter. Retain current application semantics; use synthetic integer amounts and opaque fixture IDs. Three fixed point documents per attempt in an emulator-only namespace: authority bundle (explicit synthetic actor, tenant, current grant/route/fence and availability), target (fixture state + monotonic target revision), receipt (stable operation key, semantic hash, minimal result and committed revision). Separate ten isolated fixture cohorts, two tenants represented, one fixed charge per cohort. This compact authority bundle is a test device, not proposed production denormalization or schema. No real users, records, credentials, imports, Rules changes, application collections, live endpoint or actual payment/settlement. Synthetic approval/fence not production authentication.

Derive stable key from versioned tuple tenant, actor, action namespace, operation ID; derive semantic hash from validated scope, target, expected revision, payload and command version. Authorization generation, epoch and time excluded from stable retry key. Independently obtain current fixture actor/fence inside each attempt. Read authority, target and receipt within the same transaction before any write. Verify exact scope, current grant/route, request/approval binding, target revision/state and domain amount. Authorize before returning any existing receipt. Same key/hash may return minimal receipt only if currently permitted, no second target mutation; different hash conflict. Different key cannot reuse settled target. Create receipt with exists:false and update target with transaction/current revision atomically; no external effects, no deletion or compensation, no legacy fallback. For this test target revision is incremented only by accepted commit or explicit fixture conflict injector; no application state. Do not expose receipt after revocation; treat unknown commit result as indeterminate and reconcile with fresh authorized receipt lookup, never blind retry. Recreated SDK client against same disposable running emulator tests client restart, NOT emulator persistence/recovery across backend restart.

|---|---|
| 1 normal | Exactly one target revision increment, one minimal receipt; commit contains both writes |

Use maximum three explicitly scheduled attempts/cohort; one transaction attempt per invocation, no automatic RPC or transaction retry. Maximum three point reads/attempt plus three verification point reads/cohort; no queries/listeners. At most two seed docs and one seed commit/cohort; at most one externally injected fixture update/cohort. Count before dispatch, cap all paths including error cleanup; do not retry beyond cap, failed/unknown attempt consumes budget. Stop at first invariant mismatch, wrong target, overflow, unexpected transport error, or ambiguous result outside explicit scenario.
