No real users, records, credentials, imports, Rules changes, application collections, live endpoint or actual payment/settlement. Synthetic approval/fence not production authentication.

Derive stable key from versioned tuple tenant, actor, action namespace, operation ID; derive semantic hash from validated scope, target, expected revision, payload and command version. Authorization generation, epoch and time excluded from stable retry key. Independently obtain current fixture actor/fence inside each attempt. Authorize before returning any existing receipt. Same key/hash may return minimal receipt only if currently permitted, no second target mutation; different hash conflict. Different key cannot reuse settled target. For this test target revision is incremented only by accepted commit or explicit fixture conflict injector; no application state. Do not expose receipt after revocation; treat unknown commit result as indeterminate and reconcile with fresh authorized receipt lookup, never blind retry. Recreated SDK client against same disposable running emulator tests client restart, NOT emulator persistence/recovery across backend restart.
