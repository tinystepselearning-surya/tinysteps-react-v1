## 1. Consolidated target architecture

Retain the existing React/TypeScript, Firebase Auth, Firestore and Functions investment. One modular business core, logical collections with typed records, contextual authorization, versioned contracts, append-safe evidence and bounded derived views. Existing Firestore is the default storage, not one physical database per record. Independent tenant deployment isolation requires an approved decision and proof. Preserve existing website/mobile and portal compatibility, established workflows, integrations and performance. Build replacements alongside legacy only in approved slices; reuse good current authorities. Do not create a second school identity, finance system, generic EAV database, blanket v2 namespace or arbitrary cross-domain API.

| Execution lane | Design and ownership |
|---|---|
| Experience | Existing portals plus future authorized workspaces, typed DTOs, feature flags; UI visibility never grants access |
| Command and workflow | Domain-owned typed commands, explicit transitions, replay keys, concurrency checks, bounded orchestration |
| Canonical records | One owner per business fact; stable IDs separate from Auth and provider aliases; effective dates and audit provenance |
| Operational projections | Source revision/freshness, bounded reads, rebuildable, no parallel write authority |
| Reporting and analytics | Metric definitions, aggregates, scope, unknown vs zero; no interactive ledger scans |
| Integrations | Provider IDs, credentials in approved stores, verified association/permission, retry/reconciliation; no foreign schema authority |

Coverage of frozen 18 business domains (platform/identity are shared foundations, not competing business domains): Growth & CRM, Admissions, SIS, Academic Catalogue, Learning, Assessment, Scheduling, Attendance, Student Success, Workforce, Finance, Commerce, Communication, Support, Safeguarding, Resources, Partnerships, Credentials/Reporting. D01–D10 supply initial design for all. Physical school routines, hygiene/safety, facilities/maintenance, inventory, leave and transport/daycare remain explicitly owned implementation requirements under P09; do not claim all optional future capability schemas are in the 129-record catalogue.

## 4. Typed contract and lifecycle closure packet

This is a review specification, not executable schema approval. Stable qualified item codes stay semantic. Candidate collection paths remain collision-checked only at approved scope. For every item adopt precise allowed type/range, cardinality, null/unknown, requiredness by version, validation, migration source/transform, owner/access, effective/history and index behavior. Use explicit nested typed structures rather than unrestricted objects. Identity shared fields use source contract; allocate shared/nested IDs under reviewed namespace. 
The 24 structured seeds are grouped below (count refers to record-specific fields, not shared inherited audit fields). Do not generate fabricated legacy types.

| Contract family | Required reviewed shape / validation |
|---|---|
| Profile migration (4) | migrationId, sourceCollection, sourceId strings; preserve planner original metadata, no inferred actor or live permission |
| Organisation contact/location (2) | Field allowlist, normalized contact/location types; existing legacy raw values preserved, no guessed location |
| Schedule recurrence and availability (2) | Bounded slots weekday/local HH:mm/positive duration, IANA zone, effective interval, revision, exception reference; retain current IST authority and review DST before other zones |
| Financial terms snapshots (3) | Preserve original billingRateSnapshot, teacherPayRateSnapshot, financialTermsCurrency, financialTermsSnapshotVersion where applicable; versioned exact currency/precision conversion, no replacement with current rates |
| Attendance correction changes (1) | Bounded list of verified participant references and raw before/after, expected revision, reason/actor/time, financial review link; preserve existing multi-participant correction event |
| Lesson objectives and assessment rubric/results (3) | Reviewed objective/criterion IDs and version, typed method-specific result and units; absent/unassessed distinct from zero |
| Mastery/progress (2) | Algorithm/schema version, evidence watermark, result and coverage, explicit unknown/freshness; preserve existing projections |
| School assessment distributions/scores (2) | Contextual school/year/section and checkpoint/version; validated counts and bounded distribution; denominator and domain-specific scoring; no individual inference |
| Report evidence (1) | Bounded reviewed typed references to actual evidence and version; preserve historical published report |
| Teaching QA (1) | Versioned criteria, minimized findings and reviewer; restricted visibility |
| Emergency safety (1) | Explicit minimum necessary purpose-specific fields and access/retention; no broad health dossier |
| Configuration (1) | Typed per registered key, allowed scope and validated value; no secrets/arbitrary executable JSON |
| Monthly business analytics (1) | Bounded month rows, approved metric keys and nonnegative safe counts or null; verified envelope, prior closed day, issues and coverage; preserve existing parser |

Copied legacy fields (45) remain held for exact type/nullable/source coverage; normalize only newly captured data under approved contract. No automatic retrospective backfill or loss. 
Lifecycle principles: transitions explicitly name actor, prior state/revision, validation, target, side effects, replay and failure. Preserve current source behavior until reviewed successor parity. Current helper status.ts defaults missing enrollment status to active, maps pending_teacher -> trial, pending_payment/enrolled/current/ongoing -> active and canceled -> cancelled; unknown nonempty -> unknown. Current different command-specific active sets exist. Do not treat this helper as universal authorization or adopt incomplete interface enum; distinguish raw status, normalized display, course-slot occupancy and command eligibility. For new canonical records unknown/missing fails closed where required; compatibility handles current legacy behavior unchanged until explicit decision. Session helper defaults missing to scheduled, aliases inprogress/canceled; do not use scheduled alone to materialize. Current financial earned attendance present OR historical late; new teacher marking present/absent. Financial settled alias paid remains compatibility. Domain transitions for offer publication/retirement, household/group episodes, academic-year switch, consent withdrawal, demo progression, assignment, receipt/void/settlement and archive/restore each require exact owner-approved transition table and tests; not yet all enumerated/adopted.

## 5. Security, indexes, performance, migration and recovery

[Record key/storage/scope matrix](M04_RECORD_KEY_STORAGE_SCOPE_MATRIX.md) classifies 85 tenant-scope candidates, 15 identity, 7 organisation inherited, 13 catalogue, 1 held household, 2 platform analytics and 6 conditional platform/tenant scope. This is not a permission matrix. New paths default deny; authorize verified principal, tenant eligibility/capability, resource scope, domain relationship and allowed fields at server and Rules independently; review overlapping Rules, direct SDK, callable Admin SDK bypass, jobs, native, cache, media, provider links, exports and restores. No inference from role label, household, guardian, user ID, claims or URL alone. Exact grants and revocation/freshness thresholds require owner and independent security review. Preserve current school principal reader and restricted staff profiles.

Query/index candidates already identified in M01–M03. Finalize only against approved command/query contract and actual source/deployed index baseline. Bounded date/tenant/learner/session/month queries; avoid fanout, broad scans, per-item reads or business writes on calendar view. Measure comparable source and replacement reads/writes/latency, including Rules-dependent reads, retries, mirrors, projections and index entries. Existing programme proposed review trigger >10% increase in comparable p95 latency or reads remains a proposal, not measured target. Set absolute per-workflow ceilings and freshness with owner before activation; no fictitious read budget.

Migration mapping: registry path/evidence/posture plus M01–M03 mappings provide candidate record-level and worked source-field mappings. They do NOT cover all current production fields, writer dependencies or transforms. For each affected record family pin source and destination; prove exact IDs and alias uniqueness; list every source field as retain/transform/derive/unknown/retire with owner, explicit transformation version and provenance; verify source/deployed/live evidence within approved cap. Never infer financial value or historical attendance/assessment. Keep original authoritative writes during additive build. Separate replay-safe bounded dry run, recovery evidence, batch+checkpoint, catch-up/revision conflict handling, reference/semantic/financial reconciliation, shadow parity, approved read switch, distinct write handoff, observation and explicitly authorized retirement. Rollback must preserve new writes, not simply restore stale backups. Recovery approval includes backup/PITR coverage, isolated restore, RPO/RTO, recovery of integrations and post-switch replay; do not claim live restore. No production operations authorized.
