### Proposed durable command contract (design only, not adopted schema)

Use one logical authority and one transaction owner per action. Separate stable idempotency key (tenant + canonical actor + action/command namespace + client operation ID, versioned collision-safe tuple) from canonical semantic request hash (scope, target, exact validated payload, command version and expected target revision); transient clock, authority revision and route epoch belong to fresh authorization fence, not the stable retry key. Do not rekey existing payment/session IDs. An existing receipt with same key and different hash is a conflict; same hash returns only an explicitly authorized minimal receipt, never an unconditional new allow or second write. No receipt disclosure after revocation. No raw child payload in receipt. Different keys do not bypass target state/revision or domain uniqueness constraints. Read-only actions never allocate mutation receipt or invoke writer. Before command transaction, independently resolve actor and route; in transaction read current route/authority revisions, grant, institutional memberships and domain evidence, target/ledger revision and receipt; evaluate exact command with no fallback. Commit domain state and receipt together, with monotonic per-target revision and append-only audit/event as applicable. For external effects use separately governed transactional outbox and idempotent downstream delivery, not network calls within retried transaction. On concurrent change retry only within approved bounded budget with full fresh evidence; reject expired approval, revoke, wrong scope, unknown state or mismatched idempotency hash. No direct caller-supplied approval or transaction callback. Model receipt retention and migration/rollback explicitly, never delete dedupe history while a retry remains possible. Firestore transaction reads/writes and SDK IAM bypass Rules must be measured and independently validated; no storage allocation, durable writer, receipt cleanup or emulator claimed by this increment.
