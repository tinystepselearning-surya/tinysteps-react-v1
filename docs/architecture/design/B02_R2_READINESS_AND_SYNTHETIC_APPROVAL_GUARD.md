## 2. R2.2A design and implementation

New module `scripts/verification/identity-operator-approval.mjs` and focused test file. No dependencies added. Synthetic-only fixed database and purpose, exact schema and bounded 32 KiB payload. Two distinct public Ed25519 fixture keys configured by trusted test harness; both must sign the same domain-separated, canonical JSON bytes. Canonical profile is intentionally narrow, not RFC 8785. Validate exact fields, bytes, signature lengths, signer order, source baseline and approval-packet pins, operator, issued/start/end timestamps, and synthetic-only approval ID. Maximum fixture authorization window 300000 ms and synthetic max-age threshold ceiling 300000 ms; neither sets a live business policy. Reuse accepted request lane plan validation (1–10 synthetic actors, exact roles/scope/IDs, 7 attempts/107 slots per actor, no enlarged budgets). Single attempted consumption per verifier instance (even failed attempt); immutable internal fixture plan with executableReady false; invalid input produces fixed error codes. No credentials, files, network, SDK, production adapter, key generation in module or execution entry point. Tests generate disposable keys in memory only.

Source/policy constants identify reviewed R57 baseline and current M3 packet, not measurement of the running candidate or deployed artifacts. Distinct key material is not proof of distinct people, independent approval, revocation or secure custody. Caller-supplied trust keys/clock are trusted fixture seams. Per-instance one-shot is NOT persistent replay protection, and an approval can be replayed by constructing another verifier. No wall-clock regression protection across dispatch, durable approval consumption, signing workflow, process supervision or browser approval validation. Auth ID shape is checked by existing plan validator; actual derived-ID match remains in canonical integration, not this module. Returned fixture plan is internal and must not be logged. Before any live design, bind real trust roots, actual verified executable bundle/policy/deployment, exact operation descriptors, private signed scope, durable atomic consume, expiry/revocation, dual-clock and supervised execution, endpoint/IAM and independently reviewed privacy controls. Never generalize synthetic-only constants into a production runner by changing a flag.
