### R2.2C — local durable one-time approval reservation

Revalidate both signatures and exact scope through a new existing approval verifier before any journal write. Consume by SHA-256 of fixed replay namespace plus signed approval ID, not payload digest; a validly re-signed changed plan with the same ID is rejected. Require trusted canonical absolute pre-created private local fixture directory with synthetic prefix, same uid and 0700 permissions; refuse symlink aliases, check directory identity when opened, use O_EXCL/O_NOFOLLOW, 0600 empty marker, fsync marker and directory before returning. Reject reuse across verifier instances and independent processes sharing the same journal. Check clock nonregression and expiry again after reservation. Never refund a created marker, even after expiry or child failure; fail closed on journal error. No manifest, actor identifiers, signing material or raw records stored in marker. Filename is a deterministic hash of synthetic approval ID, not an anonymization guarantee for real identifiers. Tests clean up only their own disposable directories.

Durability is conditional on a trusted local filesystem honoring exclusive create and fsync; no power-loss/rollback/remote filesystem, distributed consensus, hostile same-UID actor or ancestor rename guarantee. Caller-supplied journal location is a trusted fixture seam; a different or restored directory can replay the same approval. Live system would require independently governed stable journal identity, atomic consumption, backup/restore and failover anti-replay semantics and retention policy. Never reset/rotate journal to bypass a consumed approval.

### R2.2B — fixed synthetic child supervision

Require durable approval consumption first; then spawn only the fixed in-module Node fixture, no shell, user-selected executable or real command, no SDK or network client. The child receives only a closed scenario enum and sanitized TZ environment, no actor plan, signatures or keys. Success requires exact fixed output, zero exit and confirmed close before expiry. Poll wall and monotonic time (10 ms interval); maximum synthetic run 5000 ms or approval expiry, whichever comes first, with 100 ms graceful termination then SIGKILL and 1000 ms close watchdog. Output retained at most 1024 bytes; stderr, malformed result, nonzero exit, output overflow and deadline stop; return only fixed codes, booleans and unknown/not-started/fixture-complete outcome, not raw output. Unconfirmed close is explicitly unknown, never success. No retry or refund.

This is a fixed-child fixture, not the canonical transport workload integrated with a live supervisor. Parent event loop, synchronous filesystem calls, spawn/OS scheduling and uninterruptible processes may delay enforcement; no hard whole-process deadline, external supervisor, descendant-process containment or OS-level egress guarantee. A separate approved host boundary must independently enforce those before any live operator. No real production execution capability.
