## Purpose

B0 establishes the source-of-truth inventory before any retitle, merge, redirect, canonical, noindex, audience-taxonomy, visual, or content-quality work is attempted in B1–B12.

The key distinction is intentional:

- **77 articles visible in the blog library does not mean 77 articles are intended for indexing.**
- UI visibility, page-level robots policy, sitemap eligibility, legacy redirects, and Search Console performance are separate dimensions and must not be conflated.

## Source architecture confirmed

The current blog registry is assembled by `src/content/blog/index.ts`, which eagerly loads `src/content/blog/posts/**/*.ts` with `import.meta.glob`, normalizes the posts, applies publication-date/category overrides, and de-duplicates by slug.

The blog index (`src/pages/BlogPage.tsx`) displays published registry posts and counts all displayed posts by category. It does **not** remove articles merely because their article page is `noindex`.

Individual article robots policy is controlled by `src/lib/blogIndexingPolicy.js` and applied by `src/pages/BlogPostPage.tsx`.

The blog sitemap is generated by `scripts/generate-sitemaps.js`. Legacy intent consolidations are separately defined in `scripts/blog-consolidation-map.mjs`.

## Generated sitemap snapshot warning

`public/sitemap-blog.xml` is a generated file and the committed baseline snapshot still contains historical/retired paths from an older inventory. The build pipeline runs `gen:sitemaps` before the existing `seo:blog-consolidation` guard, so the committed XML must not be treated as the authoritative current route registry by itself.

B0 therefore compares:

1. current source posts;
2. current page-level noindex policy;
3. current sitemap-generation policy;
4. current retired redirect map; and
5. the committed generated sitemap snapshot.

Any mismatch is reported explicitly instead of changing production behavior.

## B0 audit tool

Run:

```bash
node scripts/audit-blog-baseline.mjs
```

To also write machine-readable inventory artifacts:

```bash
node scripts/audit-blog-baseline.mjs --write
```

Outputs:

- `artifacts/seo/blog-b0/blog-inventory.json`
- `artifacts/seo/blog-b0/blog-inventory.csv`

For structural CI-style failure on duplicate slugs or retired source posts:

```bash
node scripts/audit-blog-baseline.mjs --strict
```

The inventory records, per current source article:

- slug and URL;
- title;
- category and source category;
- author;
- effective publication date;
- read time;
- excerpt;
- approximate body word count;
- body-block and FAQ counts;
- hero/meta-description presence;
- internal links and external references detectable in source;
- inferred parent/school/mixed audience for triage;
- intent-cluster hint for B2 review;
- weekly-series status;
- page-level `noindex` status;
- expected sitemap status;
- committed-sitemap presence;
- retired-source status;
- obvious exposed template-artifact flags;
- source path and byte size.

## Performance columns intentionally not guessed

Before B2/B3 makes destructive SEO decisions, enrich the inventory with actual performance evidence where available:

- GSC impressions;
- GSC clicks;
- CTR;
- average position;
- top queries;
- GA4 landing sessions;
- engagement;
- CTA/demo clicks;
- inquiries;
- enrollment/qualified-lead attribution;
- ChatGPT/Bing/other referral traffic where identifiable.

If those exports are unavailable, B2 may classify intent overlap, but **must not choose a redirect winner using invented performance data**.

## B0 completion gates

B0 is complete when all of the following are true:

- [x] Every current TypeScript blog source is discoverable by one deterministic audit.
- [x] UI article count is separated from page-level indexability.
- [x] Page robots policy is separated from sitemap policy.
- [x] Existing retired redirect mappings are part of the audit.
- [x] Duplicate slugs are detectable.
- [x] Generated sitemap drift is detectable.
- [x] Template artifacts are detectable for editorial triage.
- [x] No production blog content, redirect, canonical, route, schema, or visual behavior is modified in B0.
- [ ] Performance metrics are enriched from GSC/GA4 before redirect-winner decisions in B2/B3.

## Handoff to B1

B1 may use this inventory to redesign **discovery taxonomy only** (parent help vs schools/research, category naming, navigation). It must not make B2/B3 redirect decisions early.

B1 starts from the same frozen `main` SHA and therefore does not inherit B0 code automatically. At final integration, bricks must be reviewed and applied in B0 → B12 order so dependencies are explicit rather than hidden through branch ancestry.
