# TSSA-7 — P0 Lead Measurement and Attribution Audit
**23 October 2026 · source + owner-export audit · read-only · NO production changes**

## Executive decision
**Do not interpret GA4's 322 key-event occurrences as 322 saved parent enquiries, and do not infer 64 AI-channel key events are 64 booked demos.** GA4 event-name/key-event configuration and the production Firestore `leads` source of truth were not accessible through the connected read tools. It is not safe to publish a lead conversion baseline or to declare a production lead outage.

**Recommendation:** repair measurement semantics and input validation in scoped implementation PRs, after confirming existing key-event definitions and backend lead states; preserve all current inbound enquiries and WhatsApp fallback. Do not modify SEO/Phonics routes as part of P0. Coordinate with [lead-health Issue #756](https://github.com/tinystepselearning-surya/tinysteps-react-v1/issues/756) and existing [A16 audit](../visibility-17-audits/reports/A16.md), which first identified some source gaps.

## Conversion measurement contract to approve

| Stage | Source of truth | Safe interpretation |
|---|---|---|
| Page landed | GA4 `page_view` and landing session (after measurement QA) | Visit, not parent intent |
| Form attempted | Explicit `form_submit_attempt` or existing `funnel_form_submit` pending contract | User tried to submit; still might fail |
| **Enquiry saved** | **Persisted Firestore canonical lead ID**, unique, with server timestamp and origin | Receipt of request, **not qualification** |
| Qualified parent | Lead lifecycle with confirmed `qualified` or approved derived state | First business KPI numerator |
| WhatsApp handoff | `whatsapp_click` only | Click/navigation, **not message sent** |
| Demo slot booked | Authoritative confirmed demo session / scheduling record | Booked appointment, not form save |
| Demo attended | Demo attendance status | Held class, not click |
| Student enrolled | Confirmed enrollment status | Conversion outcome |

**Primary KPI (once reconciled):** unique qualified website enquiries / external landing sessions × 1,000, grouped by channel and original landing page. Secondary: saved-lead count, channel attribution completeness, save rejection rate, valid demo bookings, attendance, enrolments, time to contact. Avoid mixing ordinary contact submissions and assessment-form `leads` collection until canonical lead ownership is defined.

## Minimal safe implementation sequence
1. **Read-only baseline gate**: GA4 Reports → Engagement → Key events/Events for 25 Sep–22 Oct, event name and count including `generate_lead`, `lead_form_submit`, `funnel_form_submit`, `funnel_demo_booking_complete`, `book_demo_click`, `whatsapp_click`; confirm which are marked key. Firestore/Admin `leads` counts by **server-created day** and lifecycle across 28 days, deduped by canonical ID; separately count `contactSubmissions`. **Only aggregate counts or redacted IDs**, no parent PII. Review October 19 incident separately (Issue #756).
2. **Scoped form validation PR**: align anonymous Firestore rule constraints to user-friendly client validation while keeping international numbers, retries and WhatsApp fallback. Add component + emulator tests. No rule relaxation or live synthetic lead submissions.
3. **Scoped event semantics PR**: keep attempt tracking and true post-save `generate_lead`, stop pre-save successful-submit semantics for this form, stop sending demo-booking-complete before a real scheduled session (after checking event consumers). Prevent retry duplicate success; version/report historical series if event definitions change.
4. **Attribution QA then scoped repair**: test marketing-vs-operational first-touch, GA4 manual-source contamination hypothesis and consent, without silently overwriting stored referral evidence. Treat source labels used for UI placement as `source_context`, not default marketing traffic source where GA4 reserves meanings.
5. **Post-change gate**: staged/emulator success/failure/double-click/mobile pop-up tests, key-event sanity, regression against source-generated insights and protected parent/private routes, monitored production after authorized deployment.
