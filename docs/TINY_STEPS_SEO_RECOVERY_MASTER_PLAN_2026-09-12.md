# Tiny Steps SEO Recovery Plan — Master Brick-by-Brick Reference

**Status:** Locked baseline plan, reconciled to implemented canonical ownership  
**Primary objective:** Recover commercial phonics visibility, remove cannibalisation, strengthen existing authority URLs, improve CTR, and avoid unnecessary SEO expansion.  
**Working principle:** **No new SEO pages during recovery. Consolidate, improve, and reinforce existing URLs.**

---

## 1. Core Strategy

Tiny Steps will **not create new SEO landing pages, city pages, “best phonics” variants, generic SATPIN guides, or keyword-variation pages** during this recovery phase.

The recovery sequence is:

> **Commercial phonics recovery → cannibalisation cleanup → SATPIN authority → parent-problem content → CTR improvements → only then reconsider new content.**

The goal is to make Google clearly understand **which Tiny Steps URL owns each important search intent**.

---

# BRICK 0 — Freeze SEO Expansion

## Objective

Stop creating additional ambiguity while the current URL structure is repaired.

## Actions

- No new SEO landing pages.
- No new city pages.
- No new “best phonics” variants.
- No new generic SATPIN guide.
- No new generic blending pages unless an existing page genuinely cannot serve the intent.
- No unnecessary URL changes on pages already earning impressions.
- No major navigation redesign during recovery.
- No mass rewrite of all blogs at once.
- No programmatic SEO expansion until the recovery cycle is complete.

## Definition of Done

The current indexable URL set is frozen and becomes the working SEO inventory.

# BRICK 4 — Merge Genuine Duplicate Pages

## Objective

Reduce index noise and combine authority.

## Confirmed Priority Candidate

Primary surviving URL after Brick 5 consolidation:

`/blog/why-child-knows-letter-sounds-but-cannot-read-words`

Historical planned owner:

`/blog/child-knows-letter-sounds-but-cannot-read` → **301** → `/blog/why-child-knows-letter-sounds-but-cannot-read-words`

Any duplicate / near-duplicate article covering the same intent should be merged into the surviving URL.

## Merge Process

1. Identify the stronger sections from both pages.
2. Consolidate them into the surviving URL.
3. Redirect retired duplicate with **301**.
4. Update:
   - canonical
   - sitemap
   - breadcrumbs
   - internal links
   - article schema
   - Open Graph URL
   - related-post cards
   - contextual links
5. Ensure no redirect chain is introduced.

## Guardrail

Only merge pages that genuinely serve the **same user intent**.

## Definition of Done

One strong URL owns the topic and all internal / technical signals point to it.

# Working Protocol for This Project

For every brick:

1. Audit the existing state.
2. Document the exact issue.
3. Make only the required changes.
4. Verify technical implementation.
5. Record what was changed.
6. Move to the next brick only after the current brick is closed.

At the end of all bricks:

1. Run a full cross-check against this master plan.
2. Verify all completion criteria.
3. Review GSC commercial-query performance.
4. Confirm query-owner consistency.
5. Close the recovery activity only after the final verification is complete.
